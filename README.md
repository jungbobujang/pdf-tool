# EDIT — PDF 작업실 · 사진 작업실 · 도장 만들기

스쿨 오리지널 편집 도구 모음입니다. 한 서비스(https://edit.up.railway.app)에 도구마다 주소가 따로 있습니다.

| 주소 | 화면 | 스쿨 도구함 |
|---|---|---|
| `/` | EDIT 입구: 도구 셋을 고르는 한 장(`public/edit/`) | — |
| `/pdf` | PDF 작업실(아래 설명 전체) | `/go/pdf` |
| `/photo` | 사진 작업실(시험 중) | `/go/photo` |
| `/stamp` | 도장 만들기 | `/go/stamp` |

- 통행증 · CSP · 안내 화면은 셋이 같이 씁니다. 안내 화면은 주소에 따라 그 도구 이름과 [스쿨에서 열기](`/go/그 도구`)를 보여 줍니다(`lib/edit-tools.js`).
- 끝에 `/`를 붙인 주소 · `index.html`은 제 주소로 돌립니다(`#` 뒤는 그대로 따라감).
- **예전 주소도 그대로 열립니다**: 스쿨이 `/#t=…&tool=이름`으로 보내거나 `/#compress` · `/#stamp` · `/#feedback`으로 오면 EDIT 입구(`public/edit/route.js`)가 그 도구 주소로 보냅니다. PDF 작업실 안 도구는 `/pdf#이름`, 사진 작업실 · 도장 만들기는 자기 주소, 이름이 없으면 `/pdf`.
- 서명 · 도장 보관(IndexedDB `pdf-workshop`, 선생님마다 따로 · 빌려 쓰는 PC는 이 탭에만)은 `public/edit/common.js` 한 곳에서 PDF 작업실과 도장 만들기가 같이 씁니다. 도장 만들기의 [PDF에 찍기]는 보관한 도장 id를 이 탭(sessionStorage)에 적고 `/pdf#decorate`로 넘어갑니다.

## PDF 작업실 (`/pdf`)

브라우저 안에서만 PDF를 다루는 웹앱입니다. 합치기, 나누기, 쪽 순서 바꾸기, 사진 변환, 꾸미기(쪽번호 · 워터마크 · 서명과 도장), 용량 줄이기, 암호를 설치 없이 쓸 수 있습니다.

**스쿨 선생님 전용 도구입니다.** 스쿨 → 도구함에서 [열기]를 눌러 엽니다. 주소만 치고 오면 안내 화면이 나오고, [스쿨에서 열기](스쿨 주소 + `/go/pdf`)를 누르면 스쿨 로그인 뒤 바로 이 화면으로 돌아옵니다(아래 "스쿨 입장권").

## 스쿨 입장권 (도구 연결 규칙 v1)

- 스쿨 도구함의 [열기]가 2분짜리 입장권을 주소 뒤 `#t=`에 붙여 새 탭을 엽니다. `#` 뒤는 서버로 가지 않아서, 안내 화면(`public/gate.js`)이 그 값을 `POST /api/enter`로 보내고 `#`을 지운 주소로 다시 엽니다.
- 서버(`lib/gate.js`)는 스쿨 공개 키(`SCHOOL_URL/api/tools/pubkey`, 1시간 캐시, 못 받으면 마지막 키, 한 번도 못 받았으면 503)로 확인합니다: 형식(머리.몸.서명) · `alg` "EdDSA"와 `kid` · Ed25519 서명 · `aud` "pdf" · `exp`(시계 차이 30초 허용) · `iat` · 처음 보는 `jti`(메모리 3분).
- 통과하면 통행증 쿠키 `pdf_pass`(가명 번호 `sub` · `sch`와 끝나는 시각, 서버 비밀로 HMAC-SHA256 서명, HttpOnly · Secure · SameSite=Lax · 8시간). 스쿨이 `#…&pc=shared`(내 교실 PC로 정하지 않은 PC)를 붙이면 통행증은 브라우저를 닫으면 사라지는 쿠키가 되고, 화면이 읽는 `pdf_who`(가명 번호의 sha256 앞 16자리: 서명 · 도장을 선생님마다 나눔) · `pdf_pc=shared`(서명 · 도장을 IndexedDB에 쓰지 않고 그 창에만, 작업 이어하기 꺼짐)를 함께 줍니다. 통행증이 없거나 틀리면 `/` · `/check` · `/privacy` · `/licenses`는 안내 화면입니다. `/version` · `/sw.js` · 라이브러리 · 안내 화면의 CSS · 아이콘은 공개입니다.
- **하위 도구 바로 열기**: 스쿨 도구함이 `#t=입장권&tool=이름`으로 열면 그 도구가 바로 열립니다. `tool=` 값은 소문자 · 숫자 · `-` 1~20자만 읽고(그 밖이면 버림), 그 가운데 지금 탭 이름(`edit` · `img2pdf` · `pdf2img` · `decorate` · `compress` · `security`)과 예전 이름(`lock` · `password` → security, `number` · `numbers` → decorate, `shrink` → compress)만 열고 나머지는 처음 화면입니다. 통행증이 없으면 안내 화면이 통행증을 받은 뒤 `#이름`만 붙인 주소로 다시 엽니다(실패 화면에서는 도구 이름을 무시). **통행증이 이미 있어도** 앱이 맨 먼저 입장권을 주소에서 지우고 같은 `POST /api/enter`로 보내 통행증을 지금 연 사람 것으로 새로 받습니다. 이 요청이 실패해도 화면은 지금 통행증으로 그대로 열리고 오류를 띄우지 않습니다. 입장권 값은 화면 · 로그 · 브라우저 저장소 어디에도 남기지 않습니다.
- `POST /api/enter`는 IP(`X-Real-IP`)당 1분 20회. 로그에는 `enter ok` / `enter fail reason=종류`만 남고 입장권 · 가명 번호 · 쿠키 값은 남지 않습니다.
- 환경 변수: `SCHOOL_URL`(기본 `https://school-production-082b.up.railway.app`). 새로 만든 비밀값은 없습니다. `PASS_SECRET`은 여러 서버를 띄우는 점검에서만 씁니다(운영에서는 넣지 않음).
- **알려진 한계**: 통행증 서명 비밀은 서버가 시작할 때마다 새로 만듭니다. 그래서 **다시 배포하면 열려 있던 선생님도 새로고침할 때 스쿨에서 [열기]를 다시 눌러야** 합니다. 이미 연 화면은 스쿨이 멈춰도 계속 쓸 수 있습니다(PDF 작업은 브라우저 안에서 하므로).

## 파일은 브라우저 밖으로 나가지 않아요 (안전 장치)

- **처리 위치**: 모든 처리는 사용자의 브라우저 안(JavaScript)에서 끝납니다. 서버는 화면을 이루는 정적 파일(HTML · CSS · JS)만 보내 주고, 파일을 받는 주소가 아예 없습니다. 결과물은 `Blob`으로 만들어 브라우저 내려받기로 저장합니다.
- **CSP(브라우저가 지키는 규칙)**: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' blob: data:; font-src 'self'; worker-src 'self' blob:; connect-src 'self'; object-src 'none'; frame-ancestors 'none'; form-action 'none'; base-uri 'self'`
  - `connect-src 'self'` 때문에 페이지가 다른 사이트로 데이터를 보낼 수 없습니다
  - `unsafe-inline` · `unsafe-eval`이 없어 끼워 넣은 스크립트 · 스타일도 막힙니다
  - 규칙 목록과 쉬운 설명은 `/check` 페이지에 서버 코드의 값 그대로 나옵니다
- **외부 자원 없음**: 라이브러리 · 글꼴 모두 CDN 없이 이 서버에서 직접 제공합니다(`/vendor/*`). 쿠키는 통행증 `pdf_pass`와 화면이 읽는 표 `pdf_who` · `pdf_pc`뿐이고, 통계 · 광고 · 외부 스크립트가 없습니다.
- **인터넷이 끊겨도(연 화면)**: 스쿨 도구함에서 연 화면은 와이파이를 꺼도 계속 작동합니다. 한가할 때 PDF 그리기 · 용량 줄이기 작업 파일을 브라우저의 보통 HTTP 캐시에 미리 받아 둡니다. 인터넷이 없으면 안심 문구 옆에 "인터넷 연결이 없어요. 이 화면은 계속 쓸 수 있지만 새로고침하면 다시 스쿨에서 열어야 해요"가 켜집니다. **새로고침하면 서버를 거치므로 스쿨에서 다시 [열기]가 필요합니다.**
- **바탕화면 설치 · 오프라인 캐시는 끝났습니다(2026-09-30)**: 서비스 워커를 등록하지 않고 `manifest.webmanifest`는 404입니다. `/sw.js`는 "끄기 워커"라서, 예전에 오프라인 워커가 깔린 브라우저 · 바탕화면 아이콘은 이 파일을 받으면 `pdfws-` 캐시를 지우고 등록을 풀고 창을 한 번 다시 엽니다(그러면 안내 화면). 옛 설치가 정리될 수 있게 **`/sw.js` 주소는 앞으로도 몇 달 남겨 둡니다.** 바탕화면 아이콘으로 열면 "바탕화면 아이콘으로는 이제 열 수 없어요 … 이 아이콘은 지워도 돼요"가 나옵니다.
- **수집 최소**: 이름 · 이메일은 받지 않습니다(`/privacy`). 스쿨이 준 가명 번호만 통행증 쿠키에 담고, 서버 파일 · DB에 저장하지 않습니다. 설정은 localStorage, 서명 · 도장 그림은 IndexedDB에 이 브라우저에만 저장됩니다. "작업 이어하기"(기본 꺼짐)를 켠 경우에만 편집 파일을 IndexedDB에 저장합니다.
- **직접 확인하는 법**(`/check`): ① 와이파이를 끄고 해 보기 ② F12 → Network 탭에 새 요청이 없는지 보기 ③ CSP 규칙 설명. 처음 화면 아래 "정말 밖으로 안 나가나요?"에서 엽니다.

### 앱 전체

- **여는 법**: 스쿨 → 도구함 → PDF 작업실 [열기]. 바탕화면 설치 · 새 버전 띠는 2026-09-30에 없앴습니다(새로 열 때마다 서버의 최신 버전).
- **새 소식**: 화면 구석 "v 커밋"을 누르면 새 소식 창(`CHANGELOG.md` → `public/changelog.json`). 새 버전을 처음 열면 버전 옆에 점, 한 번 보면 꺼짐
- **의견 보내기**: 사이드바 아래 · 푸터. 외부 설문(새 창)만 열고 파일 · 화면 내용은 보내지 않아요. 설문 주소는 `public/config.js`의 `FEEDBACK_URL`(비어 있으면 "아직 설문 주소가 없어요"). [오류 내용 복사]도 있음
- **설정**(톱니 · 푸터 [설정]): "브라우저를 닫아도 작업 이어하기"(기본 꺼짐, 편집 파일 · 순서 · 회전 · 삭제 예정을 IndexedDB에, 500MB 넘으면 저장 안 함, 다시 열면 "지난 작업을 이어 할까요? (파일 3개 · 2시간 전)"), "이 브라우저에 저장된 것 모두 지우기"(설정 · 서명 · 최근 작업, 예전 캐시 · 서비스 워커가 남아 있으면 그것까지)
- **Ctrl+V 붙여넣기**: 클립보드의 사진은 사진 → PDF(용량 줄이기 화면이면 거기)에, PDF는 편집에. "클립보드의 사진 1장을 넣었어요"
- **탭 제목**: "PDF 작업실" → "편집 중 · 파일 3개" → "알맞은 크기 찾는 중 45%". 작업 중 탭을 닫거나 새로고침하면 확인
- **인쇄**: 앱 화면에서 Ctrl+P를 누르면 "PDF를 저장한 뒤 그 파일을 인쇄하세요" 한 장만 나와요
- **오래된 브라우저**: ES2020 · CSS grid 등이 없으면(인터넷 익스플로러 · 옛 크롬) 앱 대신 "이 브라우저에서는 열 수 없어요. 엣지, 크롬, 웨일로 열어 주세요"(`public/compat.js`, ES5). 자바스크립트가 꺼져 있으면 `<noscript>`로 같은 안내
- **공유 미리보기**: Open Graph 제목 · 설명 · 1200×630 그림(`public/icons/og-image.png`). 카카오톡 · 메신저에 주소를 보내면 카드가 떠요. 파비콘 SVG · PNG · apple-touch-icon
- **안내 페이지**: `/check`(직접 확인하는 법) · `/privacy`(개인정보 안내) · `/licenses`(사용한 라이브러리, `npm run build`가 package.json에서 자동 생성)

### 저장 두 가지

- **[바로 저장]** (<kbd>Ctrl</kbd>+<kbd>S</kbd>): 묻지 않고 바로 저장해요. "이 설정 기억하기"로 저장해 둔 설정이 있어도 쓰지 않아요(늘 예측 가능하게). 브라우저의 "페이지 저장"은 막아요.
- **[설정하고 저장…]** (<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd>): 파일 이름(쓸 수 없는 `\ / : * ? " < > |`는 `_`로)과 다섯 항목을 켜고 끄는 창이 열려요.
  1. 쪽번호 2. 워터마크 3. 서명 · 도장 이미지 4. 암호 걸기(열기 암호 두 번, 인쇄 · 복사 · 편집 허용) 5. 용량 목표(`__ MB 이하로 맞추기`)
  - 오른쪽 미리보기에 실제 쪽 위로 쪽번호 · 워터마크 · 도장이 겹쳐 보이고 ◀ ▶로 쪽을 넘겨요.
  - 적용 순서: 쪽번호 → 워터마크 → 도장 → 용량 맞추기 → 암호(항상 마지막).
  - "이 설정 기억하기"는 localStorage에 저장하고, 비밀번호는 절대 저장하지 않아요. 휴대폰에서는 전체 화면 시트가 돼요.
- 편집 · 나눠 저장 · PDF → 사진 · 꾸미기 · 용량 줄이기 모두 같은 두 버튼을 써요. 나눠 저장에서 설정을 고르면 모든 파일에 적용하고 쪽번호는 파일마다 1부터예요.

### 용량 줄이기는 이렇게 해요 (`public/compress.js`)

1. **손실 없이**: 다시 저장(object stream 사용). PDF/A-1 문서는 object stream을 쓸 수 없어 없이 저장해요. 원본 그대로 목표 이하면 여기서 끝.
2. **사진만 줄이기 — 목표 안에서 최대한 선명하게**: 글자 · 글꼴은 그대로 두고 사진만 다시 만들어요.
   - **큰 사진부터** 줄이고, 목표에 닿으면 나머지 사진은 **원본 그대로** 둬요. 가장 선명한 설정(t=1)으로 몇 장만 줄여서 되면 거기서 멈추고, 모든 사진을 줄여야 하면 크기(0.35~1배)와 JPEG 품질(0.4~0.9)을 한 값 t로 묶어 **이진 탐색**(최대 7번)한 뒤 남는 만큼 작은 사진을 원본으로 되돌려요.
   - 실제로 저장한 크기로 몇 번 더 맞춰서 결과가 **목표의 85~100%**에 오게 해요(넘으면 한 장 더 줄이고, 너무 작으면 원본을 되돌림).
   - 줄여도 커지는 사진(이미 작은 것)은 원본 유지. 사진 하나를 읽지 못해도 그 사진만 원본으로 두고 "건너뛴 사진 N장(이유별)"로 알려요.
   - 읽는 형식(한글 · HWP에서 만든 PDF에 흔한 것): JPEG 회색 · RGB(브라우저 디코더), CMYK JPEG(Adobe 반전 · Decode 배열, JS 디코더), Flate 회색 · RGB · CMYK · **Indexed(팔레트) 1 · 2 · 4 · 8bit**, 1 · 2 · 4 · 16bit, **ICCBased(N=1/3/4)**, **Decode 배열**, PNG 예측, **SMask**(같은 크기로 함께 줄임). CMYK는 pdf.js와 같은 변환식으로 RGB로 바꿔요.
   - 건드리지 않는 것: JBIG2 · CCITT · 1bit 마스크("이미 작은 흑백 이미지"), JPEG 2000, Separation · DeviceN · Lab 색 공간, 색 키 마스크, 4천만 화소 넘는 사진.
3. **쪽 전체를 사진으로**(마지막 수단): 자동으로 하지 않고 "쪽을 사진으로 바꾸면 X MB까지 줄일 수 있어요. 대신 글자를 선택하거나 검색할 수 없어요." 창으로 물어본 뒤, pdf.js로 쪽을 그려 dpi · 품질을 같은 방식으로 맞춰요. 줄일 사진이 없는 글자 위주 파일도 이 창을 거쳐 쓸 수 있어요.

- 무거운 계산은 Web Worker(`compress-worker.js`, OffscreenCanvas가 있을 때)에서 돌려요. Worker가 죽거나(onerror) 30초 동안 말이 없거나 메모리가 모자라면 메인 스레드에서 사진 하나마다 쉬어 가며 다시 해요. 사진은 한 장씩 풀고 줄인 뒤 ImageBitmap을 닫고 canvas 크기를 0으로 되돌려 바로 메모리를 돌려줘요. (`?worker=0`을 주소에 붙이면 메인 스레드만 써요 — 측정용)
- 사진 파일은 canvas로 다시 인코딩해요. PNG는 투명한 곳이 있으면 WEBP(또는 PNG 유지), 없으면 JPG로 바꾸고 카드에 알려요. 휴대폰 사진 방향(EXIF)은 반영해요.
- 글자 위주 PDF는 "이 파일은 약 N MB까지만 줄일 수 있어요(대부분 글꼴이라서)"라고 미리 알려요.

### 여러 파일 일괄 처리 (보안 · 꾸미기 · 용량 줄이기)

- 파일을 2개 이상 넣으면 목록 모드: 줄마다 파일색 아이콘 · 이름 · 크기와 쪽수 · 상태 배지(대기 / 처리 중 / 완료 / 실패), 실패면 이유와 [따로 처리].
- 설정은 위에 한 번만. 한 파일씩 차례로 처리해 메모리를 아끼고, 하나가 실패해도 나머지는 계속해요. [취소]는 지금 파일까지 끝내고 멈춰요.
- 저장: [x] zip 하나로 묶기(기본), 앞에 붙일 말(예: `풀림_`), "완료된 N개 저장". 실패 목록은 [실패 목록 복사]로 오류 내용(파일 이름 빼고)을 모아 복사해요.
- zip 안의 한글 파일 이름은 UTF-8 표시(general purpose bit 11)로 저장돼 윈도우 탐색기 · `Expand-Archive`에서도 그대로 보여요(verify에서 실제로 풀어 확인).

### 파일 정보 ⓘ

편집 · 꾸미기 · 보안 · 용량 줄이기의 파일 칩에 ⓘ: 쪽수 · 크기, 쪽 크기 분포, 만든 프로그램(Creator/Producer), 잠금(열기 암호 · 권한 제한), 형식(PDF 버전 · PDF/A · 태그 PDF), 글자 유무(첫 5쪽), 만든 날짜. PDF/A면 "편집해 저장하면 PDF/A 표시는 사라져요" 안내. Esc · 바깥 클릭으로 닫히고 휴대폰에서는 아래에서 올라오는 시트.

### 오류 안내

- "처리하지 못했어요" 대신 원인별 문장으로 알려요: 메모리 부족("쪽이 많아 메모리가 부족해요. 다른 탭을 닫거나 편집에서 나눠서 줄여 보세요"), 손상된 파일, 잠긴 파일, 지원하지 않는 형식, 작업 멈춤 등.
- 모든 도구의 오류 알림에 **[오류 내용 복사]** 버튼: 오류 메시지 · 스택 앞부분 · 단계 · 쪽 번호 · 파일 크기와 쪽수 · 브라우저 정보를 글로 복사해요. **파일 이름과 내용은 넣지 않아요.**

- 편집에 파일이 하나뿐이면 쪽 캡션은 "N쪽"만, 여러 개일 때만 "파일이름 앞부분 · N쪽"으로 보입니다.
- 라이트 · 다크 모드를 모두 지원하고, 움직임 줄이기 설정도 따릅니다.
- 글꼴 Pretendard도 이 서버에서 직접 제공합니다.

## 로컬 실행

Node.js 18 이상이 필요합니다.

```bash
npm install
npm start
```

- 다크 모드 밝은 조각, 브라우저 확대 150% · 200%, 포커스 순서, 인쇄, CPU 4배 느리게 한 153쪽(썸네일 끝까지 · 3초 넘게 멈춤 없음)

`npm run verify`는 만들어 둔 `/licenses` 페이지와 새 소식 JSON이 package.json · CHANGELOG.md와 맞는지도 확인합니다.

관문이 조용히 비지 않게:

- `@playwright/test`는 devDependencies에 판을 고정해 둡니다. 처음 받은 PC는 `npm ci` 후 `npx playwright install chromium`.
- `test:ui`는 playwright를 못 불러오거나 Chromium이 없으면 건너뛰지 않고 "test:ui 실패: playwright가 없어요 → npm ci 후 npx playwright install chromium"을 찍고 종료 코드 1로 끝납니다. 실행한 검사가 0개여도 실패입니다.
- 일부러 건너뛸 때만 `SKIP_UI=1`(PowerShell은 `$env:SKIP_UI = "1"`, 끝나면 `$env:SKIP_UI = $null`). 그때는 "건너뜀(SKIP_UI)"을 크게 찍으니 관문 보고에 그대로 적어 주세요.
- `verify`는 내보내는 HTML(`public/` 전체 · 라이선스 생성기를 지금 돌린 결과)과 `server.js` · `scripts/` · `lib/`에 `<link rel="manifest"` 줄이 다시 생기지 않았는지 봅니다. `public/manifest.webmanifest` 파일 자체는 남아 있고 서버가 404로 막습니다.

### 실제 파일로 확인하기

```bash
node test/real-files.mjs "C:\경로\파일1.pdf" "C:\경로\파일2.pdf"
# 또는 PDF_TEST_FILES="경로1;경로2" node test/real-files.mjs
```

- 파일은 저장소에 넣지 않고 경로로만 읽습니다. 결과에는 파일 이름 대신 "파일 1", "파일 2"만 적습니다.
- 용량 줄이기를 node와 브라우저(Worker · 메인 스레드)에서 실제로 재 봅니다.

`test:ui`는 저장소에 설치된 playwright만 씁니다(밖에 따로 깐 것은 판이 달라질 수 있어 쓰지 않음). `UI_CHANNEL=chromium`을 주면 headless-shell 대신 정식 Chromium으로 돕니다. 같은 PC에서 다른 저장소 검사가 돌면서 Chromium을 정리하면 검사 도중 "Target page, context or browser has been closed"로 끊길 수 있으니, 그때는 다른 검사가 끝난 뒤에 돌려 주세요.

```
server.js            express 정적 서버 (+ /vendor/* 로 라이브러리 제공, 스쿨 입장권 문 · POST /api/enter)
lib/gate.js          스쿨 입장권 확인 · 통행증 쿠키 · 공개 키 캐시 · jti · 횟수 제한 (의존성 없음)
public/gate.html     안내 화면 (+ gate.css · gate.js: #t= 입장권을 /api/enter로 보냄)
public/index.html    화면 (처음 화면 + 작업 화면, 선 아이콘 SVG 스프라이트)
public/style.css     스타일 (라이트/다크, 반응형)
public/pdf-core.js   PDF 핵심 로직: 쪽 순서 순수 함수, 나눠 저장 계획(splitGroups), 워터마크, 서명·도장 자리, 걸린 제한 읽기 (브라우저와 검증 스크립트가 함께 씀)
public/guide-anim.js 사용법 패널의 움직이는 예시(작은 DOM 무대 + 시간표, 무한 반복)
public/compress.js   용량 줄이기 엔진 (1·2단계, 이진 탐색, 사진 파일) — 그림 codec만 환경마다 넘겨받음
public/compress-worker.js  용량 줄이기를 Web Worker에서 돌리는 얇은 껍데기
public/app.js        화면 동작
public/compat.js     오래된 브라우저 확인(ES5, 맨 먼저 읽힘)
public/config.js     주인이 바꾸는 설정(FEEDBACK_URL)
public/sw.js         끄기 워커(옛 오프라인 워커 · 캐시를 치우고 스스로 풀림, 몇 달 남겨 둠)
public/manifest.webmanifest  쓰지 않음(서버가 404). 지워도 되는 파일
public/icons/        로고 · 앱 아이콘 · 파비콘 · 공유 미리보기 그림 (scripts/gen-icons.mjs가 만듦)
public/pages/        안내 페이지: check.html · privacy.html · licenses.html(자동 생성)
public/pages.js      안내 페이지 공용(버전 표시, 보일 때만 예시 재생)
public/changelog.json  새 소식 (CHANGELOG.md에서 자동 생성)
test/verify.mjs      로직 검증 (용량 줄이기 실측 포함)
test/node-codec.mjs  검증용 그림 codec (jpeg-js, node에는 canvas가 없어서) + CMYK JPEG · 색 샘플 PDF 만들기
test/real-files.mjs  실제 PDF 실측 (경로로만 읽음)
lib/jpeg-decoder.js  jpeg-js 디코더를 브라우저 · Worker · node에서 성분 값으로 쓰는 감싸개 (/vendor/jpeg-decoder.js)
test/ui-check.mjs    브라우저 점검 (+ --screens 로 스크린샷)
docs/screens/        스크린샷
scripts/write-build-info.mjs  배포 직전 커밋·시각 기록 (npm run deploy)
scripts/gen-licenses.mjs   /licenses 페이지 만들기 (npm run build, --check로 확인만)
scripts/gen-changelog.mjs  CHANGELOG.md → public/changelog.json (npm run build, --check로 확인만)
scripts/gen-icons.mjs      로고 SVG로 아이콘 PNG · 공유 미리보기 그림 만들기 (playwright 필요, 로고를 바꿀 때만)
CHANGELOG.md         사용자 말로 적은 변경 기록(새 소식)
```

- [pdfjs-dist](https://github.com/mozilla/pdf.js) 3.11.174 — 썸네일, PDF → 사진
- [JSZip](https://stuk.github.io/jszip/) 3.10.1 — 여러 파일을 zip으로 묶기
- [express](https://expressjs.com/) 4.21.2 — 정적 파일 서버
- [axe-core](https://github.com/dequelabs/axe-core) 4.13.0 — 개발용, 자동 접근성 검사(ui-check)
- [Pretendard](https://github.com/orioncactus/pretendard) 1.3.9 — 글꼴 (SIL OFL). 한글 워터마크에는 `Pretendard-Bold.otf`를 `/vendor/fonts/`로 제공하고 워터마크를 쓸 때만 불러와 서브셋으로 넣음
- [@cantoo/fontkit](https://github.com/cantoo-scribe/fontkit) 2.0.12 — @cantoo/pdf-lib용 글꼴 처리(서브셋). `@pdf-lib/fontkit` 1.1.1은 Pretendard 서브셋에서 오류가 나서 이 포크를 씀. `/vendor/fontkit.min.js`

- [pako](https://github.com/nodeca/pako) 2.1.0 — PDF 안 Flate 이미지 풀기/투명도 다시 압축. `/vendor/pako.min.js`
- [jpeg-js](https://github.com/jpeg-js/jpeg-js) 0.4.4 — CMYK · Decode 배열이 있는 JPEG를 성분 값으로 풀기(`/vendor/jpeg-decoder.js`, 용량 줄이기에서 필요할 때만 불러옴) + 검증 스크립트

## 배포 (Railway)

`npm start`(= `node server.js`)로 실행되고 Railway가 주는 `PORT` 환경변수를 씁니다.

### 자동 배포 (기본)

- GitHub `main`에 push하면 Railway가 자동으로 빌드 · 배포합니다(보통 1분 안팎). 빌드 때 `npm run build`가 `/licenses` 페이지와 새 소식 JSON을 다시 만듭니다.
- 배포 뒤에는 `/version`의 commit이 push한 커밋과 같은지 확인하세요. 3분이 지나도 다르면 아래 수동 배포를 씁니다.
- 새 버전이 배포되면 이미 열어 둔 사람에게는 "새 버전이 있어요 [새로고침]" 띠가 뜹니다(서비스 워커 캐시 이름에 커밋이 들어 있어 새 버전이 옛 캐시를 교체).
- 다른 주소로 배포하면 공유 미리보기 그림 주소를 위해 `PUBLIC_URL` 환경 변수를 그 주소로 넣으세요(기본 https://edit.up.railway.app).
- 의견 설문을 붙이려면 `public/config.js`의 `FEEDBACK_URL`에 설문 주소(https)만 넣고 push하면 됩니다.

### 수동 배포: `npm run deploy` (Railway CLI 로그인 필요)

```bash
npm i -g @railway/cli   # 처음 한 번
railway login           # 처음 한 번
railway link            # 처음 한 번: 프로젝트와 서비스(pdf-tool) 고르기
npm run deploy          # build-info.json을 만들고 railway up --detach
```

- `scripts/write-build-info.mjs`가 현재 커밋 7자리와 시각을 `build-info.json`에 적습니다.
- 이 파일은 git에는 올리지 않고(`.gitignore`), `.railwayignore`의 `!build-info.json`으로 `railway up`에는 포함됩니다.
- GitHub `main`에 push하면 Railway가 자동으로도 배포합니다(서비스의 배포 트리거: `main`).

### 지금 떠 있는 버전 확인

- `GET /version` → `{"commit":"b272c47","builtAt":"…","source":"build-info"}`
- commit은 아래 순서로 찾습니다.
  1. GitHub 자동 배포: `RAILWAY_GIT_COMMIT_SHA`
  2. `npm run deploy`: `build-info.json`
  3. 로컬 실행: `git rev-parse`
- 화면에도 처음 화면 오른쪽 아래와 사이드바 맨 아래에 `v 커밋`이 작게 보입니다.
- HTML은 `Cache-Control: no-cache`로 보내고, `app.js` · `style.css` · `pdf-core.js`는 `?v=커밋`을 붙여 부릅니다. 새 커밋이 배포되면 주소가 바뀌어 옛 파일이 캐시에 남지 않습니다.
- 화면의 커밋이 GitHub 최신 커밋과 다르면 새 커밋이 배포되지 않은 것입니다. `npm run deploy`로 직접 배포하거나, Railway 서비스 설정 › Source에서 저장소 · 브랜치 연결과 자동 배포가 켜져 있는지 확인하세요.
